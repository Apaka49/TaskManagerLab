# Лабораторна робота 1: Менеджер завдань (Task Manager)

Ця лабораторна робота — мій перший крок у розробці об'єктної моделі для застосунку обліку проєктів та завдань. 

Щоб уникнути плутанини в коді та дотриматися принципів багатошарової архітектури і Single Responsibility (єдиної відповідальності), я розділив рішення на чотири окремі проєкти. Кожен з них виконує свою конкретну задачу:

- TaskManager.Storage
Це мій "фундамент" — бібліотека класів, яка відповідає виключно за зберігання сирих даних. Тут знаходяться класи ProjectStorageModel та TaskStorageModel. Згідно з вимогами, вони не мають жодних обчислюваних полів. Щоб уникнути жорсткої прив'язки, проєкти не містять списків завдань, а завдання знають лише ID свого батьківського проєкту. Також я додав сюди перечислення (enum) для типів проєктів та пріоритетів завдань.

- TaskManager.Models
Ця бібліотека відповідає за те, як дані будуть виглядати для кінцевого користувача. Тут живуть класи ProjectViewModel та TaskViewModel. Вони беруть дані зі Storage-моделей і додають до них логіку. Наприклад, саме тут я реалізував підрахунок прогресу проєкту (Progress) та перевірку, чи не прострочений дедлайн завдання (IsOverdue). Також тут проєкт нарешті отримує свій список завдань для зручного відображення.

- TaskManager.Services
Оскільки справжньої бази даних у нас поки немає, ця бібліотека імітує її роботу. Клас StorageService виступає в ролі штучного сховища. При першому запуску він сам генерує початкові тестові дані (проєкти та завдання), щоб програма не була порожньою. Також цей сервіс має методи, які дозволяють консольному застосунку отримувати потрібну інформацію.

- TaskManager.Console
Це точка входу в програму — консольний інтерфейс. Він звертається до сервісу за даними, перетворює їх у ViewModel і показує користувачеві. Через меню можна подивитися всі проєкти, вибрати потрібний, побачити його деталі (з вирахуваним прогресом) та список завдань (з відмітками про виконання та статусом дедлайну).
